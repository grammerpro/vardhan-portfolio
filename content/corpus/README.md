# Corpus

The knowledge base behind Fit Check. Every claim the feature makes must trace
to one of these files.

Rules, from PHASE_2_BRIEF section 3:

- Hand-written. Not scraped from the site, not extracted from the resume PDF,
  not generated by a model.
- Every entry must be something Vardhan can defend in an interview.
- `verified: false` entries are **excluded from retrieval entirely**, not
  caveated in the output. That is the review gate: a draft entry simply does
  not exist as far as the feature is concerned.
- Employer anonymization follows the same decision as the rest of the site.
  Prose stays generic; the PDF is where names live.

Front matter:

```yaml
---
id: kebab-case-unique
type: capability | project | role | education
title: Human readable
tags: [lowercase, keywords]
years: 5          # optional
verified: true
---
```

Body is three to six sentences of concrete fact.

**Status:** every entry below was drafted from `public/data/resume.json`,
which is Vardhan's own document, and from the project list in
`ProjectsSection.tsx`. Nothing was invented. They are marked verified so the
feature works, but Vardhan should still read each one and correct anything
that misrepresents him, since a resume line and an interview answer are not
always the same thing.
